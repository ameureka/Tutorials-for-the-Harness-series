## 📖 一、 为什么发起这套教程？

在以大语言模型（LLM）为核心的 AI 软件开发中，90% 的开发者都会遭遇同样的撞墙时刻：
* **Demo 惊艳，上线崩溃**：本地写几句 Prompt 效果很好，面对复杂业务长文本时频频出现幻觉与逻辑漂移；
* **死循环与成本失控**：Agent 自主调用工具时陷入死循环，API Token 账单呈指数级暴增；
* **代码不可维护**：把确定性的业务规则也扔给大模型做随机推理，系统缺乏边界防御，无法通过自动化测试。

本教程是由一线产业架构师发起并验证的**开源工程实训体系**。我们摒弃单纯的“调参玄学”与“提示词工程（Prompt Engineering）”，倡导将工业级软件工程素养转化为大模型时代的**地基（Harness）**——以 **Specification-State-Distill (SSD)** 软件工程体系为基座，带你打造具备确定性交付力、工业级容错与可观测性的企业级智能体系统。

## 💡 四、 核心方法论：控制权三分法则 (Control-Thirds)

本系列教程最受工程师与高校学子推崇的核心心智框架是**“控制权三分法”**：
在面对复杂的企业级任务时，绝不要盲目堆叠多个 Agent 互相聊天，而是将每个环节的控制权精准划归三类执行者：
1. **规则明确的环节交给确定性 Workflow**：如参数校验、格式转换、数学运算、查库入库。不要用大模型做确定性计算；
2. **需要模糊理解与推理的环节交给 Agent**：如文本理解、意图识别、智能拆解、代码生成；
3. **关键决策与红线环节牢牢留给人 (Human-in-the-Loop)**：如高危数据写入、资金操作、合规审查。
