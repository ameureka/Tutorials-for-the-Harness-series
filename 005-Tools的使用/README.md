## 🎯 一、 核心要点速览

1. **从单一 Function Calling 到 MCP 协议标准化**：
   * 传统 Function Calling 各厂商格式分散、绑定严重；
   * **Model Context Protocol (MCP)** 正在成为大模型时代的“USB 协议”，将本地资源（Resources）、自动化工具（Tools）与前置提示模板（Prompts）实现统一标准化抽象，让任何 Agent 可以无缝即插即用外部能力。
2. **工具调用的三大工程陷阱与防御防线**：
   * **陷阱一：模型随机伪造参数** ➔ **防线**：基于强类型 Schema（如 Zod / Pydantic）进行物理级拦截校验，参数不合法直接阻断，决不透传给数据库或底层 API；
   * **陷阱二：无限递归与死循环** ➔ **防线**：设置最大连续调用深度阈值（如 `<= 5` 轮），单次超时必须提供熔断分支；
   * **陷阱三：敏感凭证被模型盗取** ➔ **防线**：遵循金融密钥物理隔离铁律，密钥（API Keys / Secrets）只存放在后端安全宿主环境，绝对不暴露在模型可读取的上下文与入参中。
3. **闭环状态回传设计**：
   * 工具执行完毕后的错误信息不能简单抛出异常退出，而应将错误信息语义化整理后回传给 Agent，让其具备“自适应自我修复与重试”的能力。
