## 🎯 一、 为什么必须做代码级走查 (Code Review)？

在高校或个人开发中，绝大多数大模型应用在本地演示时往往看起来“很惊艳”，但一旦部署到真实网络环境、面对并发请求或异常输入时，就会瞬间暴露致命缺陷：
1. **状态随处乱飞**：前端组件直接裸调后端大模型 API，跨页面没有统一状态机持久化；
2. **缺乏降级容错**：一旦第三方大模型接口超时或返回格式错误，整站直接白屏崩溃；
3. **安全合规漏洞**：把包含用户私密信息的请求体直接透传给公网模型，未做脱敏与沙箱隔离。

本讲通过现场走查真实开发者与高校学生提交的 AI 创新大作业，带领大家经历一次脱胎换骨的**代码级重构**。

## 🔍 二、 工业级 AI 应用评审四大核心维度

在评审任何一个大模型驱动的项目时，我们必须执行以下四维严格检验：

```text
┌─────────────────────────────────────────────────────────────┐
│                 工业级 AI 原型代码走查四大防线                  │
├──────────────────────────────┬──────────────────────────────┤
│ 1. 架构解耦性 (Decoupling)    │ 2. 上下文稳定性 (Stability)   │
│ · 确定性业务不依赖 LLM 随机推理 │ · 长文本滑动窗口与截断保护   │
│ · 前后端接口严格强契约类型定义 │ · 跨会话状态持久化与状态机隔离│
├──────────────────────────────┼──────────────────────────────┤
│ 3. 工具闭环度 (Tool Safety)  │ 4. 容错与防脆弱 (Resilience)  │
│ · MCP / API 工具入参强校验   │ · 接口超时、重试与优雅降级   │
│ · 敏感 Token/密钥物理隔离    │ · 自动化评测 (Eval) 断言防线  │
└──────────────────────────────┴──────────────────────────────┘
```

## 🛠️ 三、 典型案例重构剖析：校园活动智能推荐平台

在实际走查本校卓越班学生提交的《校园活动智能推荐平台》（集成高校官方活动抓取与个性化大模型推荐）时，导师给出的核心重构点：

### 1. 原始缺陷 (Before)
* 前端组件直接发起爬虫调用，爬虫接口没有限流与异常捕获，单次网络阻塞导致前台主进程卡死；
* 每次用户刷新页面都全量触发大模型向量计算，Token 消耗高昂且响应延迟达 5 秒以上；
* 缺少合规数据过滤，直接将未清洗的网页 HTML 塞入上下文导致上下文溢出。

### 2. 重构落地 (After)
* **引入状态机与定时缓存**：数据采集移至后台异步 Worker 定时批处理，将处理后的结构化活动写入 D1 / SQLite 数据库，前台只读缓存；
* **引入轻重模型分层**：使用本地轻量正则与关键词做第一道过滤（确定性 Workflow），仅对复杂用户兴趣匹配调用轻量大模型；
* **增加容错降级分支**：大模型若在 3 秒内未返回，系统自动优雅降级为“基于热度与发布时间排序”，保证 100% 页面可用性。

## 📋 四、 开发者自查 Checklist

在提交你的作品前，请对照自问：
* [ ] 是否所有的模型返回都有 JSON Schema 强校验，而不是裸字符串解析？
* [ ] 当模型服务返回 HTTP 500 或超时，你的界面是否给出了友好的降级提示而不是报错红屏？
* [ ] 你的前端请求体中，是否彻底剔除了用户的手机号、真实姓名或未脱敏数据？
* [ ] 系统的确定性规则（如计数、排序、校验）是否交给了普通代码，而不是拜托大模型？
