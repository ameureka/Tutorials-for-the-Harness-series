## 🎯 一、 核心要点速览

1. **什么是 Harness 软件工程素养？**
   * “Harness”原指马具或测试地基。在 AI 时代，它是指**用严格的工业级软件工程脚手架（规范、断言、沙箱、容错机制）来约束大模型这匹野马**。
   * 不把希望寄托在“模型一定会聪明地答对”，而是假定“模型随时可能胡言乱语”，并为其构筑坚固的工程防线。
2. **大模型能力分层 (Model Tiering) 架构**：
   * **Tier 1 (轻量快模型)**：如 Haiku/Flash/轻量端侧模型，负责高频文本清洗、意图初筛、简单分类与格式转换，单次调用成本极低；
   * **Tier 2 (中坚主力模型)**：负责日常业务逻辑拆解、代码生成与多轮工具调用；
   * **Tier 3 (重型旗舰推理模型)**：负责复杂数学推导、核心架构决策与终审，仅在关键分支按需触发。
   * **效果**：系统整体 API 成本暴降 60%~80%，端到端响应时延大幅缩短。
3. **自动化评估器 (Eval) 与对抗性断言 (Assert)**：
   * 传统软件依靠单元测试（Unit Test），大模型系统依靠 **Eval 自动化基准测试**；
   * 设计严密的真实业务测试集，在发版部署前自动化运行，防止模型输出格式与语义漂移。

## 💡 三、 思考与实操练习

1. 在你的系统中，是否所有的简单意图判断都在直接调用最昂贵的顶级大模型？尝试将其降级为轻量模型路由。
