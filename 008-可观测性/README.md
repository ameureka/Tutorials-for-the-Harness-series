## 🎯 一、 为什么大模型系统极其依赖可观测性 (Observability)？

在传统 Web 架构中，一个接口的执行路径是确定性的；但在由大模型与智能体驱动的系统中，运行具有三大不可预测性：
1. **执行路径非确定**：同样的输入，Agent 可能会调用 1 次工具，也可能在复杂推理下调用 10 次工具；
2. **成本与时延黑盒**：单次请求的 Token 消耗可能跨越几个数量级，突发的高成本请求会迅速击穿预算；
3. **输出质量潜伏性退化**：上游模型厂商静默更新权重或微调，可能导致原先稳定的 Prompt 突然出现逻辑漂移与幻觉。

因此，**可观测性是大模型系统走出实验室、进入生产环境的前提条件**。

## 🛠️ 三、 生产级可观测性推荐技术栈与架构设计

1. **分布式链路追踪 (Tracing)**：
   * 基于 OpenTelemetry 标准规范，捕获从用户请求 ➔ Context 组装 ➔ LLM 生成 ➔ MCP Tool 执行的全链路 Span。
   * 推荐方案：OpenTelemetry + Langfuse / Phoenix 自建方案。
2. **指标采集与仪表盘 (Metrics & Dashboard)**：
   * 核心指标：`P95/P99 响应延迟`、`Prompt/Completion Token 吞吐比`、`缓存击穿率`、`工具调用失败率`。
   * 推荐方案：Prometheus + Grafana。
3. **安全审计与结构化日志 (Structured Logging)**：
   * 遵循数据安全防线：日志入库前必须对身份证、电话、金融私密密钥进行哈希或脱敏；
   * 记录完整的模型请求原始参数与温度系数，支持重放调试（Replay Debugging）。

---

## 📋 四、 生产上线前的可观测性 Checklist

* [ ] 系统是否配置了全局的单会话最大工具循环次数（如强制限制 `<= 10` 轮防止死循环）？
* [ ] 是否建立了每日 Token 预算上限告警，避免黑客刷量导致天价账单？
* [ ] 生产日志中是否已严格过滤掉包含 `sk_live`、`whsec_` 等敏感凭证的字段？
* [ ] 核心业务是否部署了自动化断言评估器（Eval），对大模型关键输出进行格式与真值校验？
